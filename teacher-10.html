1 Session Overview Step 10 · Final Step

This is the culminating step. Students apply Reinforcement Learning — specifically Q-Learning — to train a Snake AI agent. No neural network is involved: the Q-table is a Python dictionary, making the entire algorithm inspectable and debuggable by hand. The goal is conceptual mastery: students should understand the feedback loop (state → action → reward → update), not implement a full Snake simulator from scratch.

💡 Teaching note: B5 and B6 (ALPHA and GAMMA) are the most confused. Students often swap the two. Point them back to the order in the Bellman equation: target = reward + GAMMA × future, then the update uses ALPHA to blend old and target. GAMMA controls what we aim for; ALPHA controls how fast we adjust.

4 Tier 2 — Bug Answers & Explanations 3 bugs · 2 attempts

Bug 1 — Q-table initialisation

Buggy code

q_table = {}

Fixed code

q_table = defaultdict(float)

Why it matters: A plain {} raises KeyError the first time the agent sees a new (state, action) pair — which happens immediately. defaultdict(float) returns 0.0 for any unseen key, which is the correct initial Q-value (no prior knowledge). This is one of the most common real-world bugs when implementing Q-learning.

Bug 2 — Flipped epsilon condition

Buggy code

if random.random() > EPSILON: # explore?

Fixed code

if random.random() < EPSILON: # explore?

Why it matters: With the bug, random() > 0.1 is true 90% of the time — so the agent explores (random action) 90% of the time and exploits only 10%. This inverts the intended behaviour. With EPSILON=0.1, the agent should explore only 10% of the time. This class of bug (comparing in the wrong direction) is extremely common and can be hard to spot without running the training loop.

Bug 3 — Wrong reward sign

Buggy code

reward = -10 # ate food

Fixed code

reward = 10 # ate food

Why it matters: A negative reward for eating food means the agent learns to avoid food. The agent would actively dodge pellets to avoid punishment — the snake would starve by design. After many training episodes, it would find corners or loops that avoid food entirely (minimising negative reward). Ask students: "What score would you expect after 10 000 episodes with this bug?"

💡 Facilitation tip: For Bug 2, if students are stuck, ask: "With EPSILON = 0.1, how often should the agent explore? When is random.random() less than 0.1?" This usually helps them see the fix without being told.

5 Tier 3 — Model Answer

Students must complete the body of update_q() using the Bellman equation. Accept any equivalent formulation.

def update_q(state, action, reward, next_state): old_q = q_table[(state, action)] best_future = max(q_table[(next_state, a)] for a in ACTIONS) target = reward + GAMMA * best_future q_table[(state, action)] = old_q + ALPHA * (target - old_q)

Validation heuristic (used by the activity script)

The activity checks for the presence of all five identifiers: best_future, target, GAMMA (or gamma), ALPHA (or alpha), and q_table. After 2 failed attempts the student is passed through automatically (their answer is still saved).

Common student mistakes

MistakeConsequence
Omitting old_q — replacing, not blendingAgent has no memory of past; learns only from last episode
Using min instead of max for best_futureAgent learns to avoid the worst action, not seek the best
Missing the ALPHA blend — q_table[...] = targetSingle-step update (effectively ALPHA=1); unstable learning
Swapping ALPHA and GAMMA rolesVery small learning rate, agent effectively ignores future rewards

6 Tier 4 — Model Answer

Students add epsilon decay to the training loop. Requirements: start 0.5, multiply by 0.995 each episode, clamp minimum at 0.01, print every 500 episodes.

epsilon = 0.5 # start with high exploration for episode in range(10000): game = Game() state = get_state(game.snake, game.food, game.snake.direction) steps = 0 while game.running and steps < 1000: # Use local epsilon for this episode's explore/exploit decision if random.random() < epsilon: action = random.choice(ACTIONS) # explore else: q_vals = [q_table[(state, a)] for a in ACTIONS] action = ACTIONS[q_vals.index(max(q_vals))] # exploit old_score = game.score game.step(action) next_state = get_state(game.snake, game.food, game.snake.direction) if game.score > old_score: reward = 10 elif not game.running: reward = -10 else: reward = -0.1 update_q(state, action, reward, next_state) state = next_state steps += 1 # Decay epsilon after each episode (clamp at 0.01) epsilon = max(0.01, epsilon * 0.995) if episode % 500 == 0: print(f"Episode {episode:5d} | epsilon = {epsilon:.4f}")
💡 What to look for: The decay and clamp are the essential requirements. The print is a soft requirement. Stronger answers may discuss why we start high — early training needs exploration; late training needs exploitation of learned knowledge. Bonus credit: students who implement a cosine or linear decay schedule instead of multiplicative.

7 Concept Check — Keys & Explanations Pass: 4 of 5

The activity uses 0-indexed option numbering internally. Answers below are given as option text and index.

QCorrect indexCorrect option textKey teaching point
Q11 "The expected future reward for each (state, action) pair" Q-values are estimates of long-run return, not immediate reward. Distractor 0 (pixels) points at DQN/CNN, not tabular RL.
Q20 "Controls the probability of choosing a random action vs the best-known action" The explore-exploit tradeoff. Distractor 1 (speed) is a common irrelevant association.
Q32 "The agent completely forgets all past experience with every single update" ALPHA=1 means the full TD error replaces the old estimate — equivalent to no memory. Distractor 0 is the intuitive wrong answer ("faster is better").
Q41 "How much the agent values future rewards compared to immediate rewards" GAMMA=0 → greedy (only immediate reward). GAMMA=1 → fully patient. Distinguishing GAMMA from ALPHA/EPSILON is a recurring confusion point.
Q50 "It tells the agent which actions lead to good or bad outcomes over time" The reward signal is the only feedback the agent receives. All learning flows from it. Distractors target the "speed" and "state" red herrings.

8 Journal Facilitation Guide

Use these notes when giving verbal or written feedback on student journal entries.

PromptWhat a strong answer looks likeRed flags
JR1
Q-table & defaultdict		 Student explains that Q(s,a) stores expected cumulative reward, and that a dict is ideal because the state space is huge (2^11 = 2048 entries) but sparse — most (state, action) combinations may never appear in training. Confusing Q-values with immediate reward; saying the dict "stores the game state".
JR2
Explore–exploit tradeoff		 EPSILON=0 → agent gets stuck exploiting suboptimal strategies it discovered early; EPSILON=1 → agent never uses what it learned, never improves. Good answers mention that decay lets the agent transition from exploration to exploitation as it gains knowledge. Only addressing one extreme; not connecting to the training lifecycle.
JR3
Discount factor GAMMA		 GAMMA near 1 means the agent plans far ahead (strategic). GAMMA near 0 means the agent only cares about the next step. Real-world analogy: a person who saves for retirement vs one who only thinks about today's lunch. In Snake, a high GAMMA helps the agent avoid trapping itself many moves later. Confusing GAMMA with ALPHA; not providing a concrete example.
JR4
Human analogy		 Strong: maps agent→learner, state→situation, action→choice, reward→consequence. E.g., a child learning to ride a bicycle — state is balance/speed, action is steering, reward is not falling. The Q-table is like muscle memory built from repeated attempts. Vague analogies with no mapping to RL terms; confusing supervised learning ("teacher gives examples") with RL ("feedback from environment").
JR5
State representation critique		 The 11-bit state cannot represent the full snake body — it only sees 3 danger sensors. A snake that has already built a long body could cut off its own escape route many steps later, but the state says "no danger straight/left/right". Improvements: add sensors for distance to tail, encode whether an area is enclosed, or increase danger sensor range. Simply saying "11 bits is not enough" without identifying a specific failure case; proposing pixel-based CNN instead of improving the feature vector (acceptable, but should explain why).

9 Common Student Errors & Interventions

ErrorLikely causeSuggested intervention
"My Q-table is always zero" Bug 1 — used plain {}, gets KeyError and training crashes silently Ask them to print the Q-table after episode 1. If empty or error, walk through Bug 1 fix.
"Snake never improves after 10 000 episodes" Bug 2 — flipped epsilon condition. Agent explores 90% of the time. Have them print "EXPLORE" vs "EXPLOIT" for the first 20 steps. Should be ~10% explore.
"Snake avoids all food" Bug 3 — negative reward for eating. Agent learned to avoid food pellets. Ask: "What is your reward for eating food?" Positive reinforcement should be positive.
Confusing ALPHA and GAMMA Two float hyperparameters in the same equation look similar Memory trick: ALPHA → "Adjust" (how fast we adjust the estimate); GAMMA → "Gaze" (how far ahead we gaze).
"What is the state tuple again?" 11-bit state is introduced in step-10.html — students may have skipped it Direct them to step-10.html → "State representation" section. 3 danger bits + 4 direction one-hot + 4 food-direction bits = 11 bits.
Tier 4: epsilon never reaches 0.01 Missing the max(0.01, ...) clamp "What's 0.5 × 0.995 after 1000 episodes?" — it approaches 0 without a floor. max(lower_bound, value) is the standard pattern.
"KeyError: (state, action)" in Tier 3 Using q_table[state][action] (nested dict) instead of q_table[(state, action)] Demonstrate the tuple key pattern: defaultdict(float) maps a tuple key to a float, not a nested dict.
