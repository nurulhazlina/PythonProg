STEP 5 OF 10 · FACILITATOR NOTES

Bonus Food 🌟

Core concepts: for loops · range() · enumerate() · list comprehension · filter pattern

← Step 4 Student Page Step 6 →
⏱ Suggested pace: 20–25 minutes · The filter pattern (list comprehension to remove expired items) and enumerate() are the two key new ideas — worth a slow walkthrough of each.

🎯 Learning Objectives

  • Use a for loop with range() to spawn a fixed number of bonus food items
  • Use range() to generate integer sequences with start, stop, and optional step
  • Use enumerate() to iterate over a list with both index and value simultaneously
  • Apply the filter pattern (list comprehension) to remove items that meet a condition without modifying the list mid-iteration
  • Manage multiple game objects stored as a list of lists (bonus_foods)

💡 The Big Idea — Annotated Code

import time

# Bonus foods: list of [x, y, spawn_time] lists
bonus_foods = []

# Spawn 3 bonus foods at once using range()
for _ in range(3):
    bx = random.randint(0, GRID_COLS - 1)
    by = random.randint(0, GRID_ROWS - 1)
    bonus_foods.append([bx, by, time.time()])   # store position + spawn time

now = time.time()

# Draw all bonus foods using enumerate() — gives index AND item
for i, bf in enumerate(bonus_foods):
    bx, by, spawn_t = bf
    time_left = 8 - (now - spawn_t)
    colour = RED if time_left <= 2 else GOLD    # flash warning!
    pygame.draw.rect(screen, colour,
        (bx * CELL_SIZE, by * CELL_SIZE, CELL_SIZE - 2, CELL_SIZE - 2))

# Filter: remove eaten foods AND foods older than 8 seconds
bonus_foods = [
    bf for bf in bonus_foods
    if snake[0] != (bf[0], bf[1])      # not eaten
    and now - bf[2] < 8                # not expired
]

for _ in range(3):

range(3) generates 0, 1, 2 — three iterations. The underscore _ is a convention meaning "we don't care about this counter value". Emphasise that range(n) gives exactly n repetitions, starting from 0.

enumerate(bonus_foods)

Wraps a list and yields (index, item) pairs on each iteration. Without enumerate, you can loop over items but not know their position. With it, you get both: i for the index and bf for the item. Ask: "When might knowing the index matter?" (e.g., to update a specific element by position, or colour-code by index).

time.time()

Returns current time as seconds since epoch (a float). Subtracting two calls gives elapsed seconds — this is how any timed event works in Python, not just games.

Spawn time in the list

Storing [x, y, spawn_time] means each item carries its own metadata — a common pattern for game objects. Ask students: "What other properties might we store here?" This plants the seed for Step 9's OOP refactor.

Filter pattern

[item for item in list if condition] creates a new list containing only items where the condition is True. This is how we "remove" items — we rebuild the list without them.

⚠️

Why not list.remove() inside a for loop? Modifying a list while iterating it causes skipped elements — Python's for loop uses an index internally and removal shifts subsequent positions. The filter pattern avoids this entirely by creating a new list.

Tier 2 — Fix the Bugs (3 bugs)

🐛 Bug 1 — range() called with no argument

Buggy code: for _ in range():

Effect: TypeError: range expected at least 1 argument, got 0 — the program crashes immediately.

✅ Fix
for _ in range(3):

Teaching note: range() requires at least one argument — the stop value. range(3) gives 0, 1, 2 — three iterations.

🐛 Bug 2 — modifying a list while iterating

Buggy code: bonus_foods.remove(bf) inside for bf in bonus_foods:

Effect: Skips items — removal shifts the list indices mid-iteration so some bonus foods are never checked.

✅ Fix — replace the remove line with the filter pattern
bonus_foods = [bf for bf in bonus_foods if snake[0] != (bf[0], bf[1])]

Teaching note: Never modify a list you are currently iterating. The filter pattern builds a new list and replaces the old one atomically.

🐛 Bug 3 — enumerate() result not unpacked

Buggy code: for bf in enumerate(bonus_foods):

Effect: bf receives a tuple like (0, [bx, by, t]) — the subsequent bx, by, _ = bf unpacking fails with ValueError: too many values to unpack.

✅ Fix — unpack both the index and the item
for i, bf in enumerate(bonus_foods):

Teaching note: enumerate() yields pairs — always unpack into two variables: i (index) and the item name.

Tier 3 — Flash Warning for Expiring Bonus Foods

Students extend the draw loop to colour bonus foods RED when less than 2 seconds remain, GOLD otherwise. Uses enumerate() and time.time().

now = time.time()
for i, bf in enumerate(bonus_foods):
    bx, by, spawn_t = bf
    time_left = 8 - (now - spawn_t)
    colour = RED if time_left <= 2 else GOLD
    pygame.draw.rect(screen, colour,
        (bx * CELL_SIZE, by * CELL_SIZE, CELL_SIZE - 2, CELL_SIZE - 2))

Key point: enumerate() is practised here — the index i is available for per-food state if needed. The ternary RED if time_left <= 2 else GOLD is an elegant one-liner for conditional colour choice. Accept equivalent if/else blocks.

Tier 4 — Respawn System with Streak Multiplier

Students design a system that refills bonus_foods back to 3 items using range(needed) and awards double points after 2 consecutive bonus foods eaten.

# After filtering expired/eaten foods, refill to 3
needed = 3 - len(bonus_foods)
for _ in range(needed):
    bx = random.randint(0, GRID_COLS - 1)
    by = random.randint(0, GRID_ROWS - 1)
    bonus_foods.append([bx, by, time.time()])

# Streak multiplier (track separately)
streak = 0
# When bonus food eaten:
streak += 1
points = 3 * (2 if streak >= 2 else 1)   # double points on streak
score += points
# When normal food eaten OR bonus expires without being eaten:
streak = 0

Accept any design that correctly uses range(needed) to refill and a counter variable for the streak. Award full marks for clear logic even if syntax is approximate.

Reflective Journal — Suggested Strong Answers

PromptKey ideas a strong answer contains
1. When use for instead of while? Example from the game. Use for when iterating over a known collection or a fixed count (e.g., for bf in bonus_foods or for _ in range(3)). Use while when the number of iterations depends on a runtime condition (while running:). Example: spawning 3 bonus foods at once uses for _ in range(3).
2. What does range(0, 10, 2) produce? Why is the last value 8, not 10? Produces 0, 2, 4, 6, 8. The stop value (10) is exclusive — range never includes it. After 8, the next step would be 10 which equals stop, so it is excluded. There are 5 values total.
3. Why is enumerate() useful when drawing bonus foods? enumerate() gives both the index i and the item bf in each iteration. Without it you only get the item. The index lets you reference or update a specific food by its position — useful for per-food state such as a flashing phase offset unique to each food.
4. Trace the filter pattern with 3 foods — 1 eaten, 1 expired. Which remain? Start with [A, B, C] where A is the snake's position (eaten) and B is older than 8 s (expired). A fails the "not eaten" test → excluded. B fails the "not expired" test → excluded. C passes both → kept. Result: [C]. Only 1 food remains.
5. New mechanic idea + which Step 5 concepts used Accept any creative mechanic that names specific concepts. Example of strong answer: "A 'mega food' that spawns 1 per type using range(3) — I'd draw each type with a different colour using enumerate(), and use the filter pattern to remove it when eaten or after 5 seconds."

✅ Concept Check Answer Key

Correct answers: CQ_ANS = [2, 2, 3, 2, 2] (1-indexed). The student's first attempt is recorded for research; re-attempts do not count.

QAnswerQuestion & explanation
1 B (2) "What does for _ in range(5): do?"
Correct: Runs the loop body 5 times (values 0, 1, 2, 3, 4). range(5) starts at 0 and excludes 5 — five iterations total.
2 B (2) "What does range(1, 8, 2) produce?"
Correct: 1, 3, 5, 7. Starts at 1, steps by 2, stops before 8. The next value (9) exceeds stop, so it is excluded.
3 C (3) "for i, bf in enumerate(bonus_foods): — what does this give you?"
Correct: Both the index i and the item bf. enumerate() yields (index, item) tuples unpacked into two variables each iteration.
4 B (2) "Why shouldn't you call bonus_foods.remove(bf) inside a for loop?"
Correct: It shifts indices, causing the loop to skip items. Removing an element moves all subsequent elements one position earlier, so the loop's internal pointer skips one.
5 B (2) "The list comprehension … keeps which items?"
Correct: Foods less than 8 seconds old AND not yet eaten. Both conditions must be True — the food's position does not equal the snake head, AND its age is under 8 seconds.

🗣️ Teaching & Facilitation Notes

Opening hook

"How does a game spawn enemies over time? How does it 'clean up' enemies that are dead or off-screen?" Both use the same pattern students are implementing here.

Key pedagogical moment — range() and enumerate()

Draw range(3) as boxes on the board: [0] [1] [2] — three boxes. Then show enumerate(['A','B','C']) yields (0,'A'), (1,'B'), (2,'C'). Ask: "What's the difference between just iterating a list and using enumerate?" Emphasise that the index is free — you're not paying a performance cost to have it.

Key pedagogical moment — The filter pattern

Spend 5 minutes walking through the list comprehension slowly. Write on the board: "New list = [item | keep it if condition is true]". Ask students to predict which items survive before running the code.

CT connection — Abstraction

Each bonus food is a self-contained object (position + time). Ask: "What other properties might a more complex game object carry?" This plants the seed for Step 9's OOP refactor.

💡

Differentiation: Fast finishers can try adding a second type of bonus food (e.g., a "slow" power-up that halves FPS for 3 seconds) — this requires a type field stored in each [x, y, t, type] item, and using enumerate() to draw each type with a different colour.
