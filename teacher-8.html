STEP 8 OF 10  ·  FACILITATOR NOTES

Save High Score

Core concepts: file I/O  ·  open()  ·  try/except  ·  f-strings  ·  leaderboard dictionary

← Step 7 Student Page Step 9 →
⏱ Suggested pace: 25–30 minutes  ·  File I/O and try/except are the two new Python concepts — let students break the program first (delete the save file) to motivate the error handling.

🎯 Learning Objectives

  • Use open() with modes "r" and "w" to read and write text files
  • Handle FileNotFoundError with try / except
  • Use f-strings to format strings with embedded values
  • Build a simple leaderboard using a dictionary

💡 The Big Idea — Annotated Code

SCORE_FILE = "high_score.txt"

# ── Load high score from file ──
try:
    with open(SCORE_FILE, "r") as f:
        high_score = int(f.read().strip())  # strip() removes newline
except FileNotFoundError:
    high_score = 0   # first time running — file doesn't exist yet
except ValueError:
    high_score = 0   # file exists but content is not an integer

# ── Save high score to file ──
def save_score(score, high_score):
    if score > high_score:
        high_score = score
        with open(SCORE_FILE, "w") as f:
            f.write(str(high_score))
    return high_score

# ── f-string formatting ──
name = "Nurul"
score = 42
print(f"Player: {name} — Score: {score:04d}")  # → "Player: Nurul — Score: 0042"
pygame.display.set_caption(f"Snake — Score: {score}  Best: {high_score}")

# ── Leaderboard (dictionary) ──
leaderboard = {}   # {"PlayerName": best_score}

def update_leaderboard(name, score):
    if name not in leaderboard or score > leaderboard[name]:
        leaderboard[name] = score

Key concept explanations

  • with open(path, mode) as f: — the with statement ensures the file is closed even if an error occurs. "r" = read, "w" = write (overwrites), "a" = append.
  • try / except — try runs code that might fail; except ExceptionType: catches a specific error type. Always catch the most specific exception you can.
  • FileNotFoundError — raised when open() is called on a file that doesn't exist. Common in file I/O — always handle it.
  • .strip() — removes leading/trailing whitespace including (newline). A file read with f.read() often ends with a newline.
  • f-strings f"..." — embed expressions directly in strings with {variable}. {score:04d} formats as a 4-digit integer with leading zeros.

Tier 1 — Fill in the Blanks

Students complete two function skeletons: load_high_score() and save_high_score(score). Six blanks in total.

BlankCorrect answerWhy
Blank 1 — file mode in load_high_score "r" Reading an existing file requires read mode.
Blank 2 — wrapper around f.read().strip() int The file stores the score as text; int() converts it to a number for comparison.
Blank 3 — return value in except FileNotFoundError 0 First run: no file yet, so the default high score is 0.
Blank 4 — function called at start of save_high_score load_high_score Must fetch the current best before deciding whether to overwrite it.
Blank 5 — comparison operator > Only save when the new score beats the previous best.
Blank 6 — file mode in save_high_score "w" Write mode creates or overwrites the file with the new best score. 
SCORE_FILE = "highscore.txt"

def load_high_score():
    try:
        with open(SCORE_FILE, "r") as f:        # blank 1: "r"
            return int(f.read().strip())        # blank 2: int
    except FileNotFoundError:
        return 0                                # blank 3: 0

def save_high_score(score):
    best = load_high_score()                    # blank 4: load_high_score
    if score > best:                            # blank 5: >
        with open(SCORE_FILE, "w") as f:        # blank 6: "w"
            f.write(str(score))

Tier 2 — Fix the Bugs (3 bugs)

BugBuggy lineFixed lineExplanation
1 with open(SCORE_FILE, "a") as f: with open(SCORE_FILE, "r") as f: Mode "a" (append) opens for writing only, not reading. Used inside load_high_score it returns nothing readable. Must be "r".
2 return f.read().strip() return int(f.read().strip()) Without int(), the function returns a string like '42'. Comparing a string with > to an integer causes a TypeError.
3 if score < best: if score > best: The logic is inverted: using < saves the score only when it is worse than the record. Must use > to overwrite only when beaten.

Tier 3 — Extend: add two helper functions

Students add display_high_score() using an f-string and reset_high_score() that writes 0 back to the file.

def display_high_score():
    best = load_high_score()
    print(f"👑 High Score: {best}")

def reset_high_score():
    with open(SCORE_FILE, "w") as f:
        f.write("0")
    print("High score has been reset to 0.")

Accept any f-string that includes the score value. Accept deleting the file via os.remove(SCORE_FILE) as an alternative to writing 0.

Tier 4 — Create: ScoreManager class

Students build a ScoreManager that wraps all file operations and run a demo loop over [12, 45, 30, 67, 55].

class ScoreManager:
    def __init__(self, filename="highscore.txt"):
        self.filename = filename

    def load(self):
        try:
            with open(self.filename, "r") as f:
                return int(f.read().strip())
        except FileNotFoundError:
            return 0

    def save(self, score):
        best = self.load()
        if score > best:
            with open(self.filename, "w") as f:
                f.write(str(score))
            print(f"👑 New high score: {score}!")
        else:
            print(f"Score {score} did not beat the record ({best}).")

    def display(self):
        print(f"Current high score: {self.load()}")

    def reset(self):
        with open(self.filename, "w") as f:
            f.write("0")
        print("High score reset.")


# Demo
sm = ScoreManager()
sm.reset()
for score in [12, 45, 30, 67, 55]:
    print(f"\nGame ended with score: {score}")
    sm.save(score)
sm.display()

Expected output: new high score at 12, 45, 67. Scores 30 and 55 do not beat record. Final display shows 67.

Reflective Journal — Suggested Strong Answers

PromptKey ideas a strong answer contains
1. Why is except FileNotFoundError safer than bare except:? Bare except: silently catches everything — including KeyboardInterrupt and SystemExit — hiding real bugs. A specific exception catches only the expected failure and lets unexpected errors surface.
2. What does the with statement guarantee? The file is automatically closed when the block exits, even if an error occurs inside. Without it, forgetting f.close() can cause data loss or file locks if the program crashes mid-write.
3. Why is int(f.read().strip()) needed — not just f.read()? Files store everything as text. f.read() returns a string like '42 '. .strip() removes the trailing newline; int() converts the string to a number so comparisons with > work correctly.
4. When would you choose "a" (append) instead of "w" (write)? Use "a" when you want to add new lines without erasing existing content — a log file, for example. Use "w" when you want to replace the entire file, such as updating the single best score.
5. How would you store the top 3 high scores instead of just one? Read the file into a list, append the new score, sort descending, keep only the top 3, then write all three back — one per line. Or use JSON: json.dump([...], f) and json.load(f).

🗣️ Teaching & Facilitation Notes

Opening hook

"What happens to your high score if the power goes out?" For students who've played arcade games, this is intuitive. File I/O is how software remembers things beyond a single session.

Motivating try/except

Before explaining it, ask students to delete high_score.txt (or pretend they're running for the first time) and run the code without the try/except. They'll see the crash. Now add try/except and show it works. Failure first, solution second — the most memorable teaching sequence.

The "with" statement

Emphasise that with open(...) as f: automatically closes the file. Without it, forgetting f.close() can cause data loss or file locks. "It's like a responsible borrower — it returns the book before walking out the door."

f-strings vs % formatting

Some students may have seen "Score: %d" % score in older tutorials. f-strings are the modern, readable standard — steer students toward them.

CT connection — Persistence

💬

Ask: "What other game data might you want to persist across sessions? Player settings? Unlocked levels? Items? What file format would you use?" This opens the door to JSON and databases.
