STEP 7 OF 10 · FACILITATOR NOTES

Wrap-Around ⭐

Core concepts: modulo % · MOVES dictionary · Pac-Man wrap · data-driven dispatch

← Step 6 Student Concept Page Student Activity Step 8 →
⏱ Suggested pace: 25–30 minutes · Show the side-by-side: old if/elif direction chain + wall-death check → new dictionary lookup + two modulo lines. The visual compression is the hook.

🎯 Learning Objectives

  • Explain what the % (modulo) operator does and why -1 % 20 = 19 in Python
  • Apply hx = hx % GRID_COLS to replace a wall-death check with Pac-Man style wrap-around
  • Store movement vectors in a Python dictionary (MOVES = {"RIGHT": (1, 0), ...}) and look up values with a variable key
  • Identify why a dictionary is preferable to a long if/elif chain for data-driven dispatch
  • Read the head of a snake list safely using index [0]

💡 The Big Idea — Annotated Code

Before (Step 6 style — wall death + if/elif)

hx, hy = snake[0]
if direction == "RIGHT": hx += 1
elif direction == "LEFT": hx -= 1
elif direction == "UP":   hy -= 1
elif direction == "DOWN": hy += 1

# wall death
if hx < 0 or hx >= GRID_COLS or hy < 0 or hy >= GRID_ROWS:
    running = False

After (Step 7 style — MOVES dict + modulo wrap)

MOVES = {
    "RIGHT": ( 1,  0),
    "LEFT":  (-1,  0),
    "UP":    ( 0, -1),
    "DOWN":  ( 0,  1),
}

def update_game(snake, direction, food, score):
    hx, hy = snake[0]           # (1) head is always index 0
    dx, dy = MOVES[direction]   # (2) O(1) dict lookup, no if/elif needed
    hx += dx; hy += dy          # (3) apply the step
    hx = hx % GRID_COLS         # (4) wrap horizontal — handles both edges
    hy = hy % GRID_ROWS         # (5) wrap vertical
    new_head = (hx, hy)
    if new_head in snake[1:]:   # (6) self-collision only (wall-death gone!)
        return snake, food, score, False

Key changes and why they matter:

  • 4 if/elif lines → 1 dict lookup: movement vectors are data, not logic. Adding a 5th direction is one dict entry, not another elif.
  • 8-condition boundary check → 2 modulo lines: hx % GRID_COLS is always in [0, GRID_COLS) regardless of input. No branch needed.
  • Wall-death removed, self-collision kept: only the wall check is replaced; body overlap still ends the game.

Modulo reference table

ExpressionResultGame meaning
20 % 200Exits right edge → re-enters column 0
-1 % 2019Exits left edge → re-enters column 19
15 % 150Exits bottom → re-enters row 0 (top)
-1 % 1514Exits top → re-enters row 14 (bottom)

ⓘ Python’s % always returns a non-negative result when the divisor is positive — that is why -1 % 20 = 19, not -1. This differs from C and Java.

Tier 2 — Fix the Bugs (3 bugs)

Bug 1 — Wrong operator

Buggy: hx = hx / GRID_COLS

Error: Division produces a float; coordinates become fractional and Pygame crashes. The snake does not wrap — it escapes the grid.

Fix: hx = hx % GRID_COLS  —  change / to %

Bug 2 — Hardcoded dictionary key

Buggy: dx, dy = MOVES["right"]

Error: KeyError: 'right' — MOVES keys are uppercase. Even if the case matched, a literal key ignores the actual direction and the snake always goes the same way.

Fix: dx, dy = MOVES[direction]  —  use the variable.

Bug 3 — Missing head index

Buggy: hx, hy = snake

Error: ValueError: too many values to unpack — snake is a list of tuples, not a single tuple.

Fix: hx, hy = snake[0]  —  add [0] to unpack only the head.

Tier 4 — Create from Scratch

GRID_COLS = 20
GRID_ROWS = 15

MOVES = {
    "RIGHT": ( 1,  0),
    "LEFT":  (-1,  0),
    "UP":    ( 0, -1),
    "DOWN":  ( 0,  1),
}

def update_game(snake, direction, food, score):
    hx, hy = snake[0]            # unpack head
    dx, dy = MOVES[direction]    # get step vector
    hx += dx                     # apply step
    hy += dy
    hx = hx % GRID_COLS          # wrap horizontal
    hy = hy % GRID_ROWS          # wrap vertical
    new_head = (hx, hy)

    if new_head in snake[1:]:    # self-collision
        return snake, food, score, False

    snake = [new_head] + snake[:-1]   # move forward

    if new_head == food:              # food eaten
        snake = [new_head] + snake    # grow
        score += 1
        food = (random.randint(0, GRID_COLS-1),
                random.randint(0, GRID_ROWS-1))

    return snake, food, score, True

Award marks for: correct MOVES dict (4 entries), snake[0] for head, both % wraps, self-collision check, snake movement, food/score logic.

Reflective Journal — Suggested Strong Answers

PromptKey ideas a strong answer contains
1. What does % do? Why is -1 % 20 = 19?Modulo returns the remainder. Python guarantees non-negative results when the divisor is positive, so -1 % 20 = 19, not -1. Maps “one step past the left wall” to the right-most column.
2. How did 2 lines of % replace the 8-condition wall check?The old check tested 4 conditions and ended the game. Modulo keeps coordinates inside the grid automatically — no out-of-bounds value can ever exist after wrapping.
3. Dictionary vs if/elif — main advantage?Movement data (the vectors) is separated from game logic. Adding a new direction needs one dict entry, not a new elif block. The dict reads as a clear table of facts.
4. What MOVES entry makes the snake freeze?"STOP": (0, 0) — a zero vector means no displacement. The code handles it without any new if statements.
5. Grid grows to 30 cols — what changes?Only GRID_COLS = 30. The line hx = hx % GRID_COLS uses the variable, so the wrap boundary updates automatically.

🗣️ Teaching & Facilitation Notes

Opening hook — 30 seconds each

Play 30 s of Step 6 (wall death) then 30 s of Step 7 (wrap). Ask: “Which version would you play longer?” They feel the improvement immediately — now make them understand the two-line fix behind it.

Why Python’s modulo differs from C/Java

In C and Java, -1 % 20 is typically -1 (negative). Python guarantees non-negative results when the divisor is positive. Demonstrate it live in a Python shell. This catches students who Google “modulo negative” and find C examples.

The “data vs logic” mental model

Draw two columns on the board: data (what moves where) vs logic (what the game does each tick). The if/elif chain mixes them. The MOVES dict separates them. Ask: “If we add a diagonal direction, how many lines change in each version?” (1 vs 5+).

Computational Thinking link — Pattern Recognition + Abstraction

Both refactors are pattern recognition: four directions share the shape (dx, dy); both axes share the same wrap formula. The dictionary and the modulo operator are the abstractions that name those patterns.

⭐ Star step pacing tip

Step 7 is a star step — two big ideas in one. Early finishers: “Can you add a diagonal direction ("UP_RIGHT": (1, -1)) without changing any game logic?” One dict entry is all that’s needed.

Common misconception — self-collision after wrap

Students sometimes think wrap-around removes self-collision. Clarify: the snake can still bite itself if it doubles back. Only wall-death is removed.
